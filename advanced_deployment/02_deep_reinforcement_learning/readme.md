# Deep Reinforcement Learning: Deep Q-Networks (DQN)

## 1. The RL problem setup

An agent interacts with an environment over discrete timesteps: at state
`s_t`, it takes action `a_t`, receives reward `r_t`, and transitions to
state `s_{t+1}`. The goal is to learn a policy that maximizes expected
cumulative (discounted) future reward:

```
G_t = r_t + gamma * r_{t+1} + gamma^2 * r_{t+2} + ...
```

`gamma in [0, 1)` is the discount factor — controls how much the agent
values future reward vs. immediate reward.

## 2. Q-values and the Bellman equation

The action-value function `Q(s, a)` estimates the expected return from
taking action `a` in state `s` and acting optimally thereafter. It obeys
the Bellman optimality equation:

```
Q*(s, a) = E[ r + gamma * max_{a'} Q*(s', a') ]
```

Intuitively: the value of taking action `a` now equals the immediate
reward plus the discounted value of the *best* action available at the
next state.

## 3. Q-learning -> Deep Q-Networks

Classic Q-learning maintains `Q(s,a)` as a lookup table — infeasible for
continuous or large state spaces. DQN (Mnih et al., 2015) replaces the
table with a neural network `Q_theta(s, a)`, trained to satisfy the Bellman
equation approximately, by minimizing the **temporal-difference (TD)
error**:

```
L(theta) = E[ ( r + gamma * max_{a'} Q_theta_target(s', a') - Q_theta(s, a) )^2 ]
```

## 4. Two stabilization tricks that make this actually work

Naively training a single network to match a "target" that is itself
generated by that same network is unstable — the target moves every
gradient step. DQN uses two fixes, both implemented here:

**(a) Target network**: keep a separate, slowly-updated copy
`Q_theta_target` (updated by periodically copying `theta` into it, e.g.
every `N` steps) to compute the TD target's `max_a' Q(s',a')`. This holds
the regression target fixed for a while, giving the online network a
stable moving target instead of chasing a target that shifts every step.

**(b) Experience replay**: store past `(s, a, r, s', done)` transitions in
a buffer, and train on randomly-sampled *minibatches* from this buffer
rather than on transitions in the order they were experienced. This breaks
the strong temporal correlation between consecutive transitions (which
would otherwise violate the i.i.d. assumption most gradient-based training
relies on) and lets each transition be reused multiple times, improving
sample efficiency.

## 5. Epsilon-greedy exploration

The agent needs to balance **exploration** (trying actions to discover
their value) against **exploitation** (taking the currently-best-known
action). Epsilon-greedy: with probability `epsilon`, take a uniformly
random action; otherwise take `argmax_a Q(s,a)`. `epsilon` is annealed
(decayed) from a high value (e.g. 1.0, pure exploration) down to a low
value (e.g. 0.05) over training, shifting from exploration to exploitation
as the Q-estimates become more reliable.

## 6. Environment used here: a custom synthetic GridWorld

Rather than depending on `gym`/`gymnasium` (an external package this
implementation avoids to keep the dependency footprint minimal and fully
self-contained), this topic implements a small GridWorld from scratch:
an `N x N` grid, an agent starting position, a goal position, and
optionally a few "obstacle" cells with negative reward. Actions are
{up, down, left, right}; reward is -0.01 per step (encourages shorter
paths), +1 for reaching the goal (episode ends), -0.5 for hitting an
obstacle (episode ends). This is simple enough to solve with a small MLP
Q-network on CPU in a modest number of episodes, while still exercising
every real component of DQN (replay buffer, target network, epsilon decay,
TD-error minimization).

## 7. What to watch for in the results

- **Episode reward should trend upward** over training as the agent learns
  a shorter/safer path to the goal — but expect noisy, non-monotonic
  progress (this is normal for RL; a single bad epsilon-greedy random
  action can end an otherwise-good episode).
- **Episode length should trend downward** — the agent should learn to
  reach the goal in fewer steps, not just reach it at all.
- If the agent gets stuck at a suboptimal policy (e.g. oscillating between
  two cells), that's a real, reportable failure mode (over-exploitation
  before the Q-estimates are reliable, or a replay buffer too small to
  cover enough of the state space) — not something to hide.
